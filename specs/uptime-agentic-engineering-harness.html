Purpose

Turn ts-axioms-template into a verifiable agentic-engineering factory: AI implements inside enforced specs, tests, and evals, while the engineer owns architecture and judgment — so AI-built features ship to production reliably (high uptime, low OpEx) instead of accruing vibe-coding debt. The repo already enforces the deterministic half of the discipline (tests, lint, module boundaries, hooks). This plan adds the missing non-deterministic half and the operational surface around it.

Problem

Per the Day 1 paper, the line between vibe coding and agentic engineering is how outputs get verified: tests verify deterministic parts, evals (labelled datasets, rubrics, LM judges) verify non-deterministic parts. Without both, it is still vibe coding. This repo has tests but no eval harness, no agent observability, no model-routing policy, and no explicit vibe↔agentic boundary. Any future LLM/agent feature would ship ungraded — the precise failure mode (silent conceptual errors, the "80% problem", high token OpEx) the paper warns against.

Solution

Two distinct eval tracks — don't conflate them. The eval target depends on what you're building:

  • Track A — Harness evals (PRIMARY; this is what improves the template over time). The "agent" is Claude Code building features in this repo. You can't eval the next unknown feature, so you don't try — you eval the harness against a frozen, representative task set (evals/tasks.jsonl: "add a slice", "fix this bug", "do this migration"). Re-run it on every change to .claude/; a better score predicts better performance on future unknown features (same logic as Terminal Bench). /retro is the diagnosis step that proposes the changes; the frozen task set is the scoreboard that says which proposals actually generalized.
  • Track B — Product-agent evals. Only when the feature you ship is an agent (support bot, research assistant). Target = that agent's outputs, graded by a provider-agnostic JudgeClient against a feature-specific dataset + rubric.

Both tracks are shipped as template capabilities (pure core + Effect shell + CI job + docs), gated by CI like every other axiom. Every external dependency is a published door (a Context.Tag + a shared/ Schema contract) with swappable Layers, mirroring the existing DeployTarget registry. The LM judge is provider-agnostic: Anthropic is the reference adapter; Pi / OpenAI / local drop in via one Layer swap at the composition root.

Capabilities:

  1. Harness-eval loop (Track A) — evals/tasks.jsonl frozen benchmark + /retro diagnosis + ratcheting score.
  2. Product-eval harness (Track B) — provider-agnostic JudgeClient, pure rubric scoring, threshold-based CI.
  3. Coverage gate + scaffolder — agentic slices must carry a dataset + rubric (opt-in by import scan).
  4. Observability — OpenTelemetry spans (tokens/latency/cost) through a swappable exporter Layer.
  5. Model routing — pure phase→tier policy (frontier for architecture, cheap for test-gen/review).
  6. Vibe↔agentic gate — explicit boundary doc + new canon axiom blocks.

[] Phase 1: Harness-eval loop — frozen task set + /retro + ratcheting score

Track A. Make "is the template getting better?" a number that climbs. You don't eval the next unknown feature; you eval the harness against a locked benchmark, and let /retro propose the changes the benchmark then judges.

1. Build the frozen benchmark

  • [] Create evals/tasks.jsonl: ~10–20 representative jobs ("scaffold a slice with X", "fix bug Y", "do migration Z"), each with a label/expected outcome. Locked — never edited to chase a score.
  • [] Define a harness rubric: gates passed? right files touched? trajectory sane? retries within budget? (reuse the 5-dimension Verdict shape from Phase 2).

2. Runner + noise floor

  • [] harness:eval script: run each task (headless claude -p or the harness-autoagent runner) → grade → aggregate. Run each task N times; report mean ± σ.
  • [] Ratchet logic: a change keeps only if mean improves beyond the noise floor (mean ± σ); a sustained drop → flag for revert. Single-run wiggle = noise, ignored.

3. Wire /retro as the diagnosis step

  • [] Confirm .claude/skills/retro/SKILL.md is shipped (done). It mines .claude/traces/, git, PRs → ranked, enforcement-biased proposals.
  • [] Document the loop in evals/README.md: /retro proposes → apply one change → re-run harness:eval → keep what raises the score → ratchet floor.
  • [] Optional: weekly /retro + harness:eval schedule (the skill's "Headless / cron use" section).

4. Testing Strategy

The benchmark must run reproducibly and the ratchet must reject noise. Validate the loop end-to-end on one real /retro proposal.

  • [] bun run harness:eval — produces a mean±σ score over the frozen set.
  • [] Apply one trivial harness change, re-run → score delta is computed and ratchet decision is correct.
  • [] /retro on the repo emits a ranked proposal citing real signal.

Decision log (from /align session)

  • D1 — Judge dependency: Effect service behind a Tag in the runner; scoring pure in core. Provider-agnostic — Anthropic reference, Pi/OpenAI swap at composition root. Rejected: SDK in core (breaks pure-core axiom), raw fetch (violates noRestrictedGlobals), heuristic-only (can't grade trajectory/quality).
  • D2 — Determinism: threshold scoring over labelled data, judge pinned + temp 0, per-dim floors; track trend weekly. Rejected: exact-match (brittle), block-from-day-one (flake erodes trust), average-only (hides a catastrophic row).
  • D3 — Coverage trigger: opt-in by static import scan (slice imports a judge/agent door ⇒ must have dataset+rubric). Rejected: content heuristic (noisy), gate-everything (friction), honor-system doc (no enforcement).
  • D4 — Observability backend: OTel + swappable exporter Layer; console reference, OTLP adapter. Rejected: hard-wire one SaaS (lock-in), custom log format (reinvents OTel), logs-only (no drift signal).
