Purpose

Make ts-axioms-template's enforcement stack fail closed under drift and loud under deletion, so repos created from it keep their axioms enforced as they grow, rename apps, and add surfaces. Every countermeasure here is motivated by a measured decay observed in a real descendant (pi-browser-dashboard, reviewed 2026-07-09): the axioms that survived there were exactly the tool-enforced ones; every prose-only rule decayed. This plan turns that finding back on the template itself.

Problem

The audit of the descendant found five decay mechanisms, none of which the template currently resists:

Decay observed in descendantTemplate weakness that allowed it
App renamed server → daemon; every purity/funnel rule silently matched zero files, then got deletedRules scoped by path (apps/server/src/**) fail open on rename
Typecheck removed entirely — no CI job, no hook; type errors can mergeNothing asserts the enforcement stack itself exists
Web tier never had module-boundary or purity rules; cross-feature imports everywhere, 1135-line god componentsDoor bans shipped only for server paths; new surfaces inherit nothing
Typed RPC neutralized: api as any, res.json() as T, hand-mirrored types — drift fails silently“Decode at the boundary” has no lint; casting .json() is legal
22 of 59 merged PRs (~37%) were empty re-merges; ruleset uncommitted, actions unpinned — one rename already blocked merges for a daySquash-merge leaves the head branch “ahead”; governance-as-code files are deletable without trace

Solution

Two complementary layers, plus three targeted fixes:

Layer 1 — rules attach to shape, not location. Re-key every Biome rule to file suffixes and folder shapes (**/*.core.ts, **/features/**, **/platform/config.ts) with a global-deny / sanctioned-allow structure. Any app, named anything, added later, inherits the full discipline by construction — renames cannot fail open.

Layer 2 — the harness checks itself. A doctor gate (pure core + thin shell, like every other slice) structurally asserts the enforcement stack: Biome overrides and plugins present, hooks wired, CI job names ⊇ ruleset required checks, actions SHA-pinned, every workspace typechecked, canon sync intact. Deleting a gate stops being silent drift and becomes a visible, deliberate act that fails bun run test.

Targeted fixes: a GritQL rule banning .json() as T (the cast that neutralized the descendant's typed RPC), delete_branch_on_merge in the governance script (kills the empty re-merge PR class), and a canon axiom + eval task that ratchet the property permanently.

Design decisions & rejected approaches

Tamper-proofing is a non-goal

A repo owner can delete the doctor too. The goal is converting silent, incremental decay (a rename that no tool notices) into loud, deliberate acts (a diff that removes a named gate and a failing test). That is the same bet the whole template makes: enforcements compound because ignoring them requires visible effort.

Why structural asserts, not byte-equality, in the doctor

Byte-comparing configs against golden copies would make every legitimate evolution a doctor failure — that teaches people to delete the doctor (the pi repo's fate for stricter gates). Asserting shapes (“an override matching **/*.core.ts denies Date”) permits growth while catching removal.

Template-sync action (pushing enforcement-file updates to descendants) — deferred to v2

A scheduled action PRing the template's biome.json/biome-plugins//workflow diffs into forks would close the “template improved after you forked” gap. Deferred: cross-repo auth, merge-conflict UX, and descendant opt-in make it a project of its own. The doctor is deliberately shape-agnostic so a future sync lands cleanly.

Why the doctor lives inside bun run test rather than its own CI job

A dedicated job can be deleted together with its gate in one commit and the ruleset would block on a missing check only if the ruleset survived. Inside test — a required check that also runs pre-push and in the scaffold smoke — removal requires editing package.json's test script, the most-watched file in the repo. Belt: checkScriptWiring asserts the composition.

Known limits

(a) The doctor cannot verify GitHub's live ruleset/settings offline — it checks the committed contract; apply-ruleset.sh remains the reconciliation tool. (b) Grit's $x.json() as $t may need multiple branches for parenthesization, same as the max-params plugin's 6 branches — budget probe time. (c) Suffix scoping can't stop someone writing all logic in routes.ts (the “enforcement can't reach design” critique) — the mutation-testing incentive question stays open, tracked for a future retro.

Operational gotchas for the builder

From this session's scars: inside .claude/worktrees, bare-path Biome lints 0 files (pass explicit paths incl. biome-plugins/); purge *.tsbuildinfo before trusting tsc -b; Biome formats .grit files — run --write on them before committing; push with an explicit refspec when branch names differ.
